이 가이드는 가장 기본이 되는 흐름 하나를 먼저 완성하는 데 초점을 둡니다. LTM 서버를 설치하고, 초기 설정을 마친 뒤, MCP 클라이언트에 등록하고, 폴더를 인덱싱한 다음, 에이전트에서 검색해 봅니다. STM은 선택 사항이므로 기본 기억 흐름이 동작하고 나면 추가하면 됩니다.

## 1. 설치

```bash
uv tool install 'memtomem[all]'       # 또는: pipx install 'memtomem[all]'
mm --version
```

`[all]`은 Web UI, 로컬 ONNX 임베딩, 코드 청킹, 한국어 토크나이저, Ollama / OpenAI 프로바이더 클라이언트를 포함합니다. 더 작은 BM25 전용 설치는 [설치](/ko/guides/installation/#ltm-서버-memtomem)를 참고하세요.

설치 직후 `mm --version`이 예상보다 오래된 버전을 출력하면 패키지 메타데이터를 갱신하며 업그레이드하세요:

```bash
uv tool install 'memtomem[all]' --refresh
```

셸이 `mm` 자체를 찾지 못하면(`command not found`) `uv tool update-shell`을 실행하고 터미널을 다시 여세요 — [문제 해결](/ko/guides/troubleshooting/) 참고.

## 2. 초기 설정

```bash
mm init
```

마법사는 프리셋 피커로 시작합니다:

| 프리셋 | 적합한 상황 | 동작 |
|---|---|---|
| Minimal | 첫 스모크 테스트, 최소 설치 | BM25 키워드 검색만 사용 |
| English | 영어 프로젝트 대부분 | 로컬 ONNX 임베딩 + 영어 리랭커 |
| Korean | 한국어 또는 다국어 노트 | 다국어 임베딩, 리랭커, 한국어 토크나이저 |

스크립트나 CI에서는 다음을 사용할 수 있습니다:

```bash
mm init --non-interactive                   # minimal 프리셋, 프롬프트 없음
mm init --preset english --non-interactive  # 영어 프리셋, 프롬프트 없음
mm init --preset korean --non-interactive   # 한국어 프리셋, 프롬프트 없음
mm init --advanced                          # 전체 마법사
```

설정 중 Claude Code 기억, Claude 플랜, Codex CLI 기억 같은 기존 AI 에이전트 메모리 폴더를 등록해 감시 대상으로 둘 수 있습니다. 등록은 이후 변경 감시를 위한 것이므로, 기존 파일은 `mm index`로 한 번 시드하세요.

마법사는 마지막에 memtomem을 MCP 클라이언트(예: Claude Code)에 자동 등록할지 물어봅니다. 여기서 수락하면 아래 4단계는 이미 끝난 셈이며, 이 프롬프트를 건너뛴 경우에만 아래 수동 단계가 필요합니다.

## 3. 로컬 점검

에디터에 연결하기 전에 CLI가 설정과 DB를 열 수 있는지 확인합니다:

```bash
mm status
```

스토리지, 임베딩, 청크 수 요약이 보이면 정상입니다. 아직 인덱싱 전이라 청크가 0개인 것은 정상입니다.

다른 클라이언트와 전체 옵션 목록은 [MCP 클라이언트 설정](https://github.com/memtomem/memtomem/blob/main/docs/guides/mcp-clients.md)을 참고하세요.

등록 후 에이전트에게 "`mem_status`를 호출해줘"라고 요청하세요. MCP 클라이언트가 터미널에서 확인한 서버를 제대로 실행하는지 검증할 수 있습니다. 에이전트에 memtomem 도구가 보이지 않으면 [문제 해결](/ko/guides/troubleshooting/)을 참고하세요.

## 5. 기억 추가와 검색

에이전트에 의존하지 않고 전체 루프를 직접 확인할 수 있도록, 먼저 CLI로 한 번 실행해 봅니다:

```bash
mm add \
  "스테이징 배포는 docs/deploy.md의 blue-green 체크리스트를 따른다" \
  --tags "deploy,ops"
mm search "스테이징 배포 체크리스트"
```

그 다음 에이전트가 검색해야 할 노트, 문서, 코드를 인덱싱합니다:

```bash
mm index ~/notes
mm index ~/projects/my-app/docs
```

이후 MCP 클라이언트에서는 자연어로 지시하면 됩니다:

| 에이전트에 지시 | 보통 호출되는 도구 | 결과 |
|---|---|---|
| "memtomem 상태 확인" | `mem_status` | 연결 및 인덱스 요약 |
| "이 결정을 기억해줘..." | `mem_add` | 마크다운 기억으로 저장 |
| "이 docs 폴더 인덱싱해줘" | `mem_index` | 기존 파일이 검색 가능해짐 |
| "배포 체크리스트 검색" | `mem_search` | 관련 기억 스니펫 순위 목록 |

## 6. Web UI 열기

```bash
mm web --open
```

기본 Web UI는 검색, 소스, 태그, 타임라인, 설정, Context Gateway를 다루는 사용자용 화면입니다. `mm web --dev`는 대부분의 사용자에게는 필요 없는 유지보수용 페이지를 추가합니다.

## 선택 사항: STM은 나중에 추가

`memtomem-stm`은 능동적 기억 서피싱과 응답 압축을 위한 별도 프록시입니다. 위 LTM 흐름이 동작한 뒤 추가하세요:

```bash
uv tool install memtomem-stm
mms init --mcp claude   # 업스트림 서버 하나를 입력받고, STM을 Claude Code에 등록
```

`mms init`은 업스트림 MCP 서버 하나(이름, prefix, command)를 추가하도록 안내한 뒤 3가지 클라이언트 등록(Claude Code / `.mcp.json` 작성 / 건너뛰기)을 제안합니다. 완료 후 읽기 전용 명령 3개로 설정을 확인하세요:

```bash
mms list      # 등록한 업스트림 목록(및 SURFACING 열)
mms status    # 설정 요약 — 프록시가 활성화되어 올바른 파일을 가리키는가?
mms health    # 업스트림 연결성과 LTM 서피싱 준비 상태 점검
```

Claude Code가 아닌 클라이언트에서는 한 줄 command 블록으로 STM을 수동 등록합니다:

```json
{
  "mcpServers": {
    "mms": { "command": "mms" }
  }
}
```

STM의 프록시 도구는 `<prefix>__<tool>` 형태로 노출됩니다. 등록 후 프록시 도구가 사라진다면 대부분 합성된 `mcp__<server>__<prefix>__<tool>` 이름이 MCP의 64자 제한을 넘었기 때문입니다 — 해결 방법(더 짧은 prefix, 또는 짧은 클라이언트 이름으로 등록)은 [문제 해결](/ko/guides/troubleshooting/)을 참고하세요.

STM이 맞지 않으면 `mms eject`로 각 서버를 원래 호스트 설정으로 되돌릴 수 있으므로, 프록시 뒤로 옮기는 작업은 되돌릴 수 있습니다.

도구 응답 압축이나 자동 기억 주입이 필요해질 때 [STM 개요](/ko/stm/overview/)를 참고하세요.
